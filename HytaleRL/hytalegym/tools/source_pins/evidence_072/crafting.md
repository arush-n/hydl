## Notes (findings outside the claim wording; for the owner)

1. Generated-recipe id split (0.7.2 and 0.5.10): Item.processConfig gives a generated recipe primaryOutput = the item id and id = "<item>_Recipe_Generated_<index>" (CraftingRecipe.generateIdFromItemRecipe). The craft gate tests the item id; DiagramCraftingWindow filters and learns by getId(). Consequence on 0.7.2 bytecode: a window-learned recipe fails the craft gate, and an item-learned recipe (LearnRecipeInteraction) is hidden by the window filter. All 1,637 generated recipes are affected; 25 are knowledge-required. Not measured live.
2. Augment tags: 50 generated recipes (inside item assets) require augment tags, e.g. goblin_lab_power on the Goblin_Painting replicas; 0 explicit recipes do. On 0.7.2, benchHasRequiredAugmentTags therefore refuses those recipes at a bench whose granted tags lack the tag, while the claim (and 0.5.10) would accept them. The earlier 'no installed effect' reading was wrong: I counted explicit recipes only.
3. Pin drift on 0.7.2 (audit reader, nav_craft/corpus.py): explicit 403 -> 410, generated 1,544 -> 1,637, total 1,947 -> 2,047, knowledge_required 19 -> 25, resource_selector_inputs 974 -> 988; tag, metadata and maximum-count pins unchanged; maximum_outputs witness tuple gains Salvage_Weapon_Mace_Scrap.json.
4. Line-number drift in bridge citations: NativeEnvironmentSession literal-zero craftable count is near lines 6567-6590 (cited 2728-2747, which is a reset block); BaseBuilderTask 386-397 matches.
5. FieldCraftingWindow has no container of its own; its craft path is CraftingWindow.craftSimpleItem (BACKPACK_STORAGE_HOTBAR).
6. Method note: Java `assert` guards (CraftingManager.craftItem, giveOutput, LearnRecipeInteraction) are disabled without -ea; the next dereference would throw on a null Player.
7. Lane scratch: scripts/offs.py was overwritten by another process during this pass; all reads used nav_craft/off.py.
