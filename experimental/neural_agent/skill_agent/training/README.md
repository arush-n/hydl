# skill_agent/training/ — data and trainers

Training runs only from the plan the owner approved (`../docs/TRAINING_PLAN.md`). Private data (traces, datasets,
checkpoints) stays under `agent_skills/training_runs/` and is never staged.

| Module | Lines | What it holds |
|---|---:|---|
| `traces.py` | 222 | Native NPC trace ingestion: recorded `NpcTraceFrame` batches as arrays with a documented schema (A7). |
| `bc_dataset.py` | 751 | The behaviour-cloning dataset from those traces on the gen-7 surface; the compass labelled in the commanded body frame (v4); the self token's head yaw offset (v5). |
| `bc_smoke.py` | 235 | B2's smoke: a tiny behaviour-cloning body held out by world, and the trained body run through the combiner. |
| `distill.py` | 754 | The A2 reference trainer: DAgger distillation of walk_to and look_at together into one generalist head (runs A2 to C', README 2.16), kept to reproduce those runs; per-skill training (2.17) replaced it as the training design. It uses `blocks.py` and the two skills' `skill.py`. |
| `bars.py` | 217 | A report scored on its bars on held success, the first hit beside: a skill module's report (per lane kind: T5, held out, the skills beside it, E4) or an A2 reference report (per mode, with a skill filter). A holding skill (track) is barred on its share: T5 at most 10 points under the teacher, held out at least 0.9 of seen (2026-10-24). |
| `blocks.py` | 312 | The building blocks every trainer shares (moved from `distill.py`, 2026-10-19): frames, request features, resampling, the hold rule, legality, dataset chunks, saving and loading, run provenance. |
| `sequences.py` | 349 | Training through time on the v3 trunk (`../docs/TRAINING_PLAN.md` 8.2 item 2, stage G1; V1 adds the packed recording, `cut` with a stride and per-lane ends, and `take`): `record` keeps each rollout decision after the state layer (tokens, object slots, the stores' new objects, resets, the carried state), packed to its valid rows with `dtype` and the carry kept only at `carry_at`; `cut` makes sequences of up to L decisions that never cross a reset, each with its stored start, overlapping by L minus the stride; `take` picks sequences (packed or dense); `unroll` re-runs the trunk over them (`lax.scan` over `step`, pure JAX); `pack` and `unpack` keep the valid rows in float16 or float32. |
| `distill_v3.py` | 648 | The V1 reference trainer (`../docs/TRAINING_PLAN.md` 8.3 and 8.8; 2026-10-23): A2's walk_to and look_at task, teachers and evaluation (reused from `distill.py`), with run C''s options by default (walk_to v3's stop margin, the look direction in the head's frame; README 2.16), on the v3 state layer, with the agent's own pose as its channel, and a trunk with memory, trained through time on stored sequences (burn-in of 30 on 90, R2D2). Each batch is cut to the token slots the data fills (`_filled`: 39 of 356 on the flat world; the same values to float32 rounding, 6 to 13 times faster). `--control` is the memory-less run, `--smoke` one iteration of 300 steps, `--params-out` saves the trained parameters. |
| `export_v1.py` | 108 | B2's export (2026-10-24): V1's trained run (`distill_v3 --params-out`) as one trunk and one `SkillModule` per skill (`walk_to`, `look_at`) on it, each with its verb, scope and the verbs it reads, the run's generalist parameters unchanged; `--arm` is `memory` or `control`; `manifest.json` carries the run's report bars, the arm, the date and the commit; a folder that holds files is refused. The arms are V1's configuration as trained (`as_trained`: without the `sound` type, which V1 predates), and the saved layout covers the trunk's own types. |
| `skill_dagger.py` | 532 | DAgger for one skill's module on the frozen trunk (2.17): lanes, requests, the teachers of the skill and of the skills beside it, rollout, loss, training, evaluation per lane kind, and the command line every skill's `train.py` shares (`run_main`). |
| `skill_dagger_v3.py` | 768 | `skill_dagger`'s method on the v3 trunk (`../docs/TRAINING_PLAN.md` 8.3, stage V2; 2026-10-24): the frozen V1 trunk runs with its carried state under the state layer, each decision's trunk outputs (context and valid token rows, float16) are stored with the masks, requests and labels, and the module alone is fitted on them. `--skill NAME` (walk_to, look_at, come_here, track) `--trunk TRUNK.npz [--smoke] --out REPORT.json --module-out MODULE.npz`; the report is `skill_module_v1`, scored by `bars.py --skill`; a holding skill's report carries `share` and `counted_lanes` per lane kind. Two gaps closed for come_here (2026-10-24, defaults unchanged): entity 1 spawns where the trained skill's goals place it (`placed_other`; walk_to's and look_at's goals place nothing, so they still spawn it at `blocks.OTHER_XYZ`), and each request's entity handle is resolved to its token row every decision (`state_tick.point`; walk_to's and look_at's pointers are -1, so unchanged). Opt-in for track (2026-10-24, defaults unchanged): a holding skill (`SkillSpec.holding`) has no done, and its counted ticks (`counts`, inside its horizon) and the ticks in view among them are the trace's `counted` and `counted_ok`; a trained skill whose goals carry a `mover` runs the environment with that path (`FlatTaskEnvironment.with_mover`). `--init-module MODULE.npz` (2026-10-24) starts the module from a trained one on the same trunk, scope and sizes (`start_module`; a dependent skill from its prerequisite, as come_here from walk_to's); the report records it as `init_module`. Speed (2026-10-25, bit-exact, defaults unchanged): `rollout`'s `shortcut` skips the work no output reads: with every lane on its teacher and nothing recorded or logged, the trunk, layer, requests and module do not run (the evaluations' teacher policy); with every lane on its teacher and the rollout recorded, the module does not run (iteration 0's collection); the four evaluations share one set of compiled kernels. `shortcut=False` is the reference the trace and report tests compare with (`test_sa_trainer_speed.py`). Measured end to end (walk_to and track, 1 iteration x 50 steps, 256 eval lanes, the machine loaded: load 21 at the start, up to 99 by the end of the after runs): 817 s to 591 s and 816 s to 593 s; the two reports match in every number except timings. A decision fills 39 of 356 token slots (the report's `token_slots`), so the trunk's padding was the largest remaining cost. Two levers, both not bit-exact (owner's rulings, 2026-10-25): `slot_cut` is on by default (`--no-slot-cut` runs the trunk on every slot, the exact path of earlier runs; the report gains a `speed` key when it is not that path), and runs the trunk on each token type's filled slots only (through the last valid row, rounded up to 8 slots, never shrinking within a rollout; object slots cut with them, as `distill_v3._batch` cuts a batch); `compact_lanes` (`--compact-lanes`, opt-in, stays off) runs the layer, trunk, requests and module only on lanes still inside their horizon or the `HOLD_TICKS` hold after it, in buckets of 16 lanes, and the other lanes act by their teachers (the environment still steps every lane). Identity probes (walk_to and track, the timing config's seeds, 256 evaluation lanes): the stored trunk outputs differ from the default by at most 1e-5 (float32 rounding); no executed action differs inside a horizon; the evaluation numbers are unchanged with `slot_cut` on both skills and with `compact_lanes` on track; Before the pace fix, `compact_lanes` changed walk_to's `pace` (steady lanes 24 to 230 at 256 lanes), because pace counted steady decisions past the horizon; pace now counts in-episode decisions only (walk_to's README), and with it the walk_to probe's evaluation summary equals the default's (0 of 22 numbers differ). Re-scoring the saved modules under the new pace (evaluation only, the old path reproduces the reports' numbers exactly): V2 walk_to seen 0.9777 to 0.9777, held out 1.0000 to 1.0000; come_here 6x2000 seen 0.8990 to 0.8990, held out 0.8621 to 0.8663; come_here from walk_to seen 0.8877 to 0.8877, held out 0.8607 to 0.8650; no E4 verdict flips (0.95 bar). Warm rollouts, one batch (load 80 to 114): walk_to collects 128 lanes in 115 s by default, 38 s with `slot_cut`, 62 s with `compact_lanes`, 37 s with both; evaluates 256 lanes in 161 s, 75 s, 80 s and 38 s. The report carries a `speed` key when either is on. |
| `run_distill.sh` | 25 | The A2 reference trainer's launcher: one run at nice 10 on the CPU, `run_distill.sh NAME ITERATIONS LANES STEPS EVAL_LANES [options]`, into the private runs folder, refusing a name that exists, on the gen-7 render by default (`engine.sh`, rendered into the run's `engine/`). Skills train through their own `train.sh`. |
| `engine.sh` | 23 | The engine a launcher runs on (2026-10-20, owner: train on gen 7): sourced with `ENGINE_DIR` set, it sets `PYTHON_M`; GEN=7, the default, renders gen 7 from the committed source into `ENGINE_DIR` and mounts it (`../runtime/gen7.py`), GEN=5 keeps the stock engine. The reference, the skills' `train.sh` and `certify.sh` use it. |
