# skill_agent/runtime/ — running skills: the registry, the combiner, programs, the scratchpad

Everything that turns the middle layer's requests into one factored action per agent per tick, and sends the
statuses back. Fixed and exact: the thinking happens inside the bodies (`../model/`), not here.

| Module | Lines | What it holds |
|---|---:|---|
| `combiner.py` | 504 | The fixed greedy combiner: per tick and per agent, check each request, grant it by scope (atomically), run the granted bodies, merge their heads, stream the statuses (R1 to R6); `BodyStep`, `AgentContext`, `StubBody`. |
| `library.py` | 458 | `SkillLibrary`: create, register and use verbs and programs; `from_catalogue()` registers the catalogue's verbs and programs; `combiner(layout)` builds one combiner per episode. |
| `programs.py` | 140 | `ProgramRunner`: an activity program (stages in order, the steps of a stage together, for-each) as a stream of requests, with the statuses read back. |
| `scratchpad.py` | 221 | The combiner on S_t: requests in from the shared state's `requests` section, statuses out to `skills`; `CombiningDecider` puts it behind the program executor (B3). With `actor_verbs` its `on_tick` returns the tick's grants as a `GrantedActor`'s state, for the session's per-tick seam (2026-10-19), and writes the actor's reports onto each granted request's status (`progress`), where the decision layer and the LLM read them (`docs/IDEAS.md` idea 8). |
| `sim_adapter.py` | 131 | `HeadAdapter`: the combiner's 21 choices onto the heads a simulator implements (neutral elsewhere), with the drops counted. |
| `parity.py` | 184 | Today's one goal per lane as one request through the combiner path (A6). |
| `joint_check.py` | 104 | B3's joint check: the composition arms with and without the combiner on S_t behind the middle layer's program executor. |
| `neural_pursuit.py` | 226 | The spine's skill (2026-10-19): the A2 C' network composing walk_to and look_at as the decision layer's `pursuit`, in the dispatcher's `Skill` protocol, from the legal observation only. Its body yaw comes from published fields: the head yaw minus the target's head-frame bearing less its body-frame bearing (exact while the target is visible), or the perception channel's body yaw on gen 7. With the target out of sight it walks to the request's remembered position, and with nothing known it turns to search (18 degrees a tick in the flat world). |
| `granted_actor.py` | 147 | The referee controls the body (2026-10-19, owner): `GrantedActor`, the ADK actor whose state is the combiner's active-request table; each scope's heads take the choices of the body granted there, a free scope stays neutral, no stand-in skill acts and the goal index is not read. Every verb's body also reports `scripted_bodies.REPORTS` each tick (`diagnostics["reports"]`), with its request's position for the bodies in `POSITION_BODIES`; a verb that holds no scope has no position. `grants_table` lowers a tick's grants; `referee_library` gives the host combiner `continuous` bodies so grants hold until withdrawn. |
| `scripted_bodies.py` | 554 | The skill layer's scripted bodies (owner: scripted first), and what each reports every tick (`REPORTS`: seen, distance, facing_me, in_reach, acting, position_used: the body could place its request's position, 0 when the request sent one that was ignored for want of the perception channel or by a body outside `POSITION_BODIES`). A target out of sight is remembered from the request's world position through the perception channel's own position and body yaw (gen 7); the evader and avoid keep moving the way they face when they cannot place the threat; `avoid` (retreat beyond a band) and `hide` (to a cover point, else retreat) join the combat bodies: `evader`, `sword` and `punish` (the weapon's first ability: in the gym a weapon attacks through its ability slots; within the held weapon's reach, `reach`, found by the first ability's id: 3.5 blocks for the sword and the mace, 3.25 for the battleaxe, 2.2 for the daggers), `guard` (on the target's wind-up), `keep_range` (its `band_min` to `band_max`), `idle`; `shortbow` (2026-10-20): `hold_seconds` picks the draw tier (`draw_tier`, the authored thresholds 0.1 to 1.2 s), the head aims through the gaze heads where the target will be when the arrow arrives (its velocity times the flight from `arrow_pitch` plus a tick; an arrow keeps none of the shooter's motion), the pitch from `arrow_pitch` (the engine's own arrow flight, with the bow read from the running engine by `bow_tiers`), and the tier is tapped once the aim is within a degree; legal observation and action mask only. |
| `gen7.py` | 115 | Runs any skill-layer module or script on a private gen-7 render (owner, 2026-10-19: gen 7 now): renders the 0.7.2 overlay into a directory and mounts it before `hytalegym` is imported; the render's import finder serves the v3 legacy module aliases (`render.py`, 780b5de). `--construct NAME` switches a gen-7 construct on in this process only (`perception_v2`, the perception channel). With `HYTALEGYM_RENDER_CACHE` set, `--render` mounts the shared render for the same source and overlay (`render.render_cached`: rendered on a miss, read in place on a hit) and does not write `--engine`; unset, it renders into `--engine` as before (2026-10-25). |
| `spine.py` | 135 | The working spine: `run_composition` up to three ways (`--runs`): the stand-in pursuit (gen 5 only), the neural one in the registry's pursuit slot, and the referee, where the combiner's grants drive the skill layer's bodies through `GrantedActor` (no stand-in acts); every host decider behind the combiner on S_t; the arms' metrics side by side and the statuses streamed. |
| `state_tick.py` | 631 | The body's path on token schema v3 (2026-10-22, step 1b of `../docs/VIRTUAL_HUMAN.md` section 13): `tick` runs the state layer, then the trunk once for every agent with its latent memory and background summary, reading each important thing's object latent from its store slot and writing it back (step 1c, section 18); `trunk_step` (2026-10-23, stage G1) is that trunk half on tokens the layer has already stepped, the same reads and writes the training unroll repeats (`../training/sequences.py`); `entity_rows` and `point` resolve a request's entity handle to its token row, perceived or remembered; `module_factors` is a skill module's masked action for every agent; `encode_contexts` and `ModuleBody` do the same through the combiner (2026-10-24: `encode_contexts` takes each agent's pose, decision tick and legal action mask, `AgentView` carries them, and `ModuleBody` drives only the trained heads of its scope (`training/blocks.HEAD_NAMES`) with the masked argmax; its `Lowering` is `(request, pose, tick)`, the skills' `lowering`). The v1 path (`../model/freezing.py`) is unchanged. `step_lanes` (2026-10-22; compiled since 2026-10-24: `tick` is jitted once per trunk config and set of fixed keywords, 20.6 ms a tick at batch 2 instead of about 1 s eagerly, equal to the eager tick to float32 rounding): the host loop's call: each lane's top-layer writes at a decision (`shared_state.skill_writes.writes_for_tick`, the coordinator's), checked by `state/written.py` `lower`, then `tick` with `respawn`, `outcomes` and `outcome_verbs`; it returns the writes' refusal reasons for `record_write_results` (`../docs/VIRTUAL_HUMAN.md` sections 19 to 21). `host_inputs` and `own_pose_channel` (2026-10-22): what the host's binding maps a session transition to: the gym's 12 heads padded to the 21 gen-7 heads, `done` as `reset`, and, where the gym publishes no perception channel (the multi-actor duel path), the agent's own position and body yaw as one (`OwnPose`: proprioception only; entity kinds, roles and the inventory read empty). `known_entities` (2026-10-22): each lane's known entities from the entity store, by the ids this layer perceives (the owner's ruling: the decision layer names entities by them), visible ones first, with where, how long ago, hostility, attitude and health, for the shared scratchpad at a decision. Since section 27 (2026-10-23): `tick(..., tick_seconds=)` passes the world's tick length to `layer.step` (gen 7's by default; a gen-5 world passes `state/clock.GEN5_TICK_SECONDS`), and `known_entities`' `dt_seconds` defaults to gen 7's. 2026-10-24 (B3, the architecture test's seam): `ModuleBody(layout=, report_done=)` builds the request slots its module was trained with (`V1_LAYOUT` for V1, `v2_layout(skill, beside)` for the DAgger trainers, verb names in slot order; a verb with no live request leaves its slot empty) and reports done when the module's done logit is above 0 (`report_done` False by default, the old behaviour); `encode_contexts(live_requests=)` hands a body a `JointView(agent, live)` carrying the agent's live requests by verb name (without it the body gets the 5-field `AgentView`, as before); `own_pose_channel` caches its NamedTuple class per observation field names, so the host's per-tick calls no longer retrace the compiled tick. 2026-10-25 (B4, the owner's speed ask; opt-in, the per-agent path unchanged): `ModuleBatch(module, trunk, lower, layout=, report_done=)` runs one skill module over the N agents of its verb in one pass: `run(view, agent_views, requests)` gives each agent the step its `ModuleBody` gives on the same inputs (same choices and done; `outputs` returns the logits, equal to float32 rounding), with agent counts padded to multiples of 8 so a changing count does not recompile; `ModuleBody(batch_results=)` returns the stored step for an agent's (row, tick) the host has batched, and computes as before otherwise; `run_module_batches(view, contexts, bodies_by_verb, requests_by_agent)` builds the host's per-tick batch for each verb (verb -> {(row, tick): BodyStep}). The request lowering (2026-10-25, B5): `_slots_rows` lowers each verb's requests for the N agents in one call by its skill folder's `lowering_batch` (a numpy batch, equal row by row to its `lowering`) where the folder has one, and per agent otherwise; `_slots` (per agent, `ModuleBody.requests`) keeps the per-agent lowering; `_requests` stacks the agents. |

Run (from the repo root). Both take `--out` and pass every other flag to the composition run they wrap, so `--help`
lists only `--out`:

```sh
JAX_PLATFORMS=cpu .venv/bin/python -m experimental.neural_agent.skill_agent.runtime.parity \
    --arms flat,j0,shuffled,j1 --ticks 64 --batch 8 --episodes 1 --seed 0 --out <dir>
NA_PROGRAM=J0 JAX_PLATFORMS=cpu .venv/bin/python -m experimental.neural_agent.skill_agent.runtime.joint_check --out <dir> \
    --arms flat,j0,shuffled,jprog --runner eager --ticks 64 --batch 8 --episodes 1 --seed 0
NA_PROGRAM=J0 JAX_PLATFORMS=cpu .venv/bin/python -m experimental.neural_agent.skill_agent.runtime.spine --out <dir> \
    --arms jprog --runner eager --ticks 512 --batch 8 --episodes 2 --seed 0
JAX_PLATFORMS=cpu .venv/bin/python -m experimental.neural_agent.skill_agent.runtime.gen7 --engine <dir> [--render] \
    -- <module or script.py> [args]
```
